MCP · solo el porqué

El proceso del agente nunca tiene el token de la API

Propósito: que la sala se lleve el porqué de MCP que da la clase: aislar las credenciales. El punto no es que “el modelo no ve las claves” (eso vale para cualquier herramienta que escribas tú), sino que el proceso del agente nunca tiene el token de la API de abajo: si hay una inyección de prompt o una fuga desde el agente, ese token no está ahí para sacarlo. No es un tutorial; otros ponentes cubren MCP. (1:00)

MCP tiene muchas razones. La que me llevo hoy, la de la clase de CMU, es el aislamiento de credenciales.
Que el modelo no vea las claves no distingue a MCP. Lo que sí: el token de la API vive en el servidor MCP, no en el proceso del agente. Si una inyección de prompt logra que el agente suelte lo que tiene en memoria, ese token no está ahí.
Misma idea que la compuerta: el modelo propone, quien tiene las llaves ejecuta.

Pasos con →: 1 el modelo propone un tool_use; 2 el agente llama al servidor con su clave MCP; 3 el servidor llama a la API con el token real, y el recuadro punteado dice que ese token no está en el proceso del agente; 4 el resultado vuelve como tool_result y la consecuencia.

Fuente: clase de CMU 11-768, lección 2 (diapositivas 44–45, “credential brokering”): el agente usa su propia clave MCP, el servidor llama a la API con otra, y el modelo no ve ninguna. La clase aclara que las claves estáticas son para enseñanza y que en producción se usan JWT u OAuth.

La consecuencia sobre la inyección de prompt (“no puede sacar lo que el proceso no tiene”) es razonamiento nuestro a partir de esa arquitectura, no una cita de la clase: dilo así. Y tiene un límite: el agente SÍ tiene su clave MCP, así que una fuga puede exponer esa clave, acotada a lo que el servidor le permite; la autorización de cada llamada sigue siendo del servidor. No afirmes que MCP “resuelve la seguridad”.

No es un tutorial y no hay demo de MCP en vivo. Si preguntan por detalles de MCP, remite a las otras charlas del evento.

Pregunta para llevarse: ¿qué token de tu agente está en la memoria o en las variables de entorno de un proceso que lee texto no confiable?
