Minuto 22 · strict: true

Válido no significa correcto

Lo que strict: true asegura

  • El input sigue el input_schema.
  • El name es una de tus herramientas.
  • Los argumentos llegan con el tipo correcto.

Lo que no puede asegurar

  • Que la llamada sea sensata, autorizada o correcta.
  • Que sea la herramienta adecuada, ni que la tarea salga bien.
  • Reglas que el esquema no expresa: sin minimum/maximum ni minLength/maxLength.
input de sql_query · dos llamadas que cumplen el esquema{"sql": "SELECT nombre FROM clientes LIMIT 5"} ✓ forma válida {"sql": "DROP TABLE tarjetas"} ✓ forma válida · ✕ no debería ejecutarse

Propósito: separar dos preguntas que se confunden: “¿tiene la forma correcta?” (lo resuelve el esquema) y “¿debe ejecutarse?” (lo resuelve la aplicación). (2:30, de los cuales ~0:45 son la historia)

La restricción asegura forma. No asegura verdad, ni permisos, ni que sea la herramienta correcta, ni que la tarea salga bien.
Un DROP TABLE es un SQL perfectamente bien formado.
